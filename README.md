# xaux_gui

## 运行

```bash
go run src/main.go
```

录音由进程内的 `pkg/ffaudio` 完成，不需要在 `PATH` 中安装或配置外部录音程序。

### Linux 构建和音频

Linux 使用 PulseAudio 采集麦克风和扬声器对应的 monitor source；也可以使用提供 PulseAudio 兼容服务的 PipeWire。需要运行中的音频服务和可访问的设备。Debian/Ubuntu 可安装构建依赖：

```bash
sudo apt install build-essential pkg-config libpulse-dev libgl1-mesa-dev xorg-dev libgtk-3-dev
go build -o xaux_gui ./src
```

使用 `go.mod` 指定版本或更新版本的 Go，且不能禁用 cgo。扬声器采集使用所选输出设备的 monitor；麦克风列表不包含 monitor source。音频由服务端转换为采集请求的格式，再由程序转换成 16 kHz 单声道 PCM。如果连接音频服务失败或设备不可用，应用会报告错误。

Linux 使用未修改的上游 PulseAudio 采集后端，其实际采集缓冲和恢复延迟由音频服务决定，可能大于请求的缓冲时长。隔离虚拟设备测试中，扬声器暂停后恢复采集曾需要约 2 秒；实际设备和服务的表现可能不同。

首页直接显示扬声器和麦克风设备选择；从 **开始 > 设置** 配置大模型参数和会话目录。**关于 > 版本显示** 可查看软件构建版本及主要第三方组件信息。

在 **开始 > 设置 > 界面语言** 可选择简体中文或 English；默认简体中文，选择会保存在应用偏好中并在下次启动时恢复。主菜单、设置、录音、转写、面试、会话历史及版本窗口会即时更新，切换不会翻译或更改用户输入、既有会话内容或模型输出。应用的确认、信息和错误对话框使用打开时选择的语言；已打开的这些对话框及新建转写会话弹窗需关闭后重新打开才会切换。当前仍有部分错误提示尚未翻译，系统原生窗口及 Fyne 自带控件的文字可能跟随系统语言。

在 **开始 > 设置 > 面试资料** 中可选择并启用 UTF-8 Markdown 简历（`.md` 或 `.markdown`）。简历路径和启用状态保存在全局应用偏好设置中，下次启动会恢复。简历为可选项；启用后，每次开始面试时读取一次，用于该次面试的实时回答，不用于面试复盘或转写总结。文件为空、不可读、格式不符或超过 32 KiB 时会提示并阻止开始；修改文件后需重新开始面试才会生效。

设置的“面试资料”中还可以启用知识文件夹，放入常见面试题、回答思路和技巧。开始面试时读取该文件夹**直接包含的** UTF-8 `.md`、`.markdown` 和 `.txt` 文件，不读取子文件夹。最多 64 个文件，合并后的内容（含分隔符）不超过 32 KiB；空文件、不可读文件或超出限制会提示并阻止开始。文件在会话开始时加载一次，修改后需重新开始面试。

## GUI 直接录音

通过菜单 **语音 → 录音** 打开录音窗口。窗口按“开始”页的勾选结果启用麦克风和扬声器，未选中的音源显示为不可用；使用统一的“开始”和“结束”控制录音。两路分别显示状态、错误信息和完整文件路径，同时录音时保存为独立 WAV 文件，不进行混音。

此窗口只测试和保存设备音频，不连接 ASR 代理。设备可在首页勾选并选择；输出固定为 **16 kHz、单声道、signed int16 WAV**。关闭录音窗口或退出程序会停止采集并完成 WAV 文件。

## 转写

从顶部 **语音 > 转写** 打开独立任务窗口。转写内容按设备和时间排列；识别中的内容会在同一段内更新，长句自动换行。页面默认跟随最新结果，手动向上查看历史时不会被新结果拉回底部，可通过“回到最新”恢复跟随。使用“暂停/继续”可暂停或恢复音频采集与识别，使用“停止并保存”结束任务并保存转写。转写、面试和录音窗口互斥。

## 面试

在首页选择音频设备；从顶部 **开始 > 设置** 配置会话目录和大模型参数，包括兼容服务的 API Key、模型名称及系统提示词，关闭设置窗口时自动保存。随后从 **语音 > 面试** 打开独立任务窗口开始会话。扬声器的最终转写结合最近对话由模型判断是否需要候选人作答，同时在后台提前生成回答；确认是问题后显示正式回答，寒暄、陈述等不会生成正式回答，也不会中断已有回答。判断可能出错，非提问、无法判断或判断失败时，可在左侧对应记录点击 **生成提示** 手动触发。判断使用单独的模型请求，只发送最近最多 8 条对话（每条最多 1000 字符），不发送职位描述、简历或面试知识；并行的回答请求即使最终判定为非问题也可能产生费用，并会发送启用的参考资料。生成提示时要求先给最多三个关键词，再给一至两句简短思路，供快速联想而非照读；实际输出仍取决于模型。麦克风转写不会单独触发回答，但会作为候选人的历史回答加入后续上下文。每次回答请求会带上最近 32 条最终对话，供模型关联前序问题和回答；有新问题到达时，会取消过时的未完成回答，优先生成最新问题的建议。结束会话时，尚未完成的 ASR 中间文本也会标记为未完成并保存，供之后复盘。

开始面试时可通过 **启用中间转写预测** 控制提前预测，默认启用，选择会被记住。每句扬声器转写至少收到 8 次去重后的有效中间更新、且去除首尾空白后达到 15 个 Unicode 字符时，模型开始预判断；此后每次预判断至少间隔一次有效中间更新，转写本身仍逐次显示。同一句同时只运行一次预判断，期间的更新会合并到下一次判断。预判为问题时会提前显示标记为“预测中”的临时回答，问题尚未说完，内容可能不准确或被撤回。最终整句到达后，重新并行发起问题判断和基于完整文本的回答请求；确认是问题之前不会展示最终请求的结果。最终判断确认是问题后，预测内容保留在界面上，最终回答追加在其下方；最终判断为非问题、失败或无法判断时撤回预测。临时回答不会保存为正式会话记录。较短的发言可能不会触发提前预测，但不影响最终处理。预测会增加模型请求和费用，也会提前向配置的模型服务发送中间转写及启用的参考资料；可关闭该选项以恢复仅在最终转写后生成的行为。

知识文件是简单的参考资料，不是语义检索：启用后，每次面试实时请求都会发送全部已加载的知识内容及启用的简历，由模型判断相关性。知识文件不会用于面试复盘或转写总结，也不会复制到会话目录。较多内容可能增加延迟和费用；请勿放入不希望发送给模型服务的信息。模型可能误解问题或输出不准确的信息，提示仅供参考。

点击 **语音 > 面试** 后，可填写会话名称并粘贴可选的职位描述（JD，最多 32 KiB）。职位描述随会话保存，可在历史中查看和复制，并用于该次面试的实时回答及面试复盘；不填写时不影响开始。职位描述和启用的简历内容会发送至配置的模型服务，请确认其中不含不希望向该服务提供的信息。简历仅记录文件路径与启用状态，不会复制到会话目录；职位描述以文本文件保存在会话目录，请注意本地文件隐私。

程序使用 Go 的 `go-openai` 客户端直接调用配置的 OpenAI 兼容 Chat Completions 服务，不需要安装或配置命令行工具或 Agent。大模型请求不经过本地 Proxy；语音识别仍沿用现有 ASR Proxy。转写文本会发送到配置的模型服务，费用和数据处理方式遵循该服务的规则。若使用火山引擎 Coding Plan，地址必须使用 `/api/coding/v3`；`/api/v3` 不会使用套餐额度，可能产生额外费用。本功能目前不含知识库检索、联网搜索或 TTS。

结束面试后，从顶部 **历史 > 会话历史** 选择面试会话并点击“一键生成复盘”。复盘侧重回答亮点、待改进项和下一步面试的练习建议。转写会话则可生成通用的 AI 总结，概括主题、观点和明确的结论或待办事项，不预设内容为面试。两者分别保存在会话目录中，可查看、复制或重新生成；没有转写的纯录音会话不提供 AI 总结或复盘。生成时会将转写发送到配置的模型服务。

为了降低实时建议的等待时间，Kimi K3 系列默认使用较低思考强度；思考期间界面会显示“思考中”，不会显示模型的内部思考文本。面试诊断日志保存在 `%APPDATA%\fyne\xaux_gui\interview_debug.log`，**应用启动时会清空上次日志**，需要跨次分析时请在重启前复制。日志按 `session`、`turn` 和模型 `request_id` 关联各阶段；`kind=interim_classification` 是中间结果预判断，`kind=interim_answer` 是临时预测回答，`kind=classification` 是最终问题判断，`kind=speculative_answer` 是最终转写后的并行预生成，`kind=manual_answer` 是手动生成。记录内容包括 ASR 中间/最终事件及界面排队、中间预测、最终转写到检查入队/判断/回答标签更新的耗时、检查队列等待、网络连接与首字节、模型思考和回答片段到达、缓存及界面更新。`-1` 表示该时间点不可用；`last_interim_to_final_ms` 是最后一次已接受的中间识别结果到最终结果的间隔，并非说话结束到识别完成的时间。界面更新耗时表示标签更新，不代表屏幕实际绘制完成；日志本身也会产生少量开销。日志不主动记录 API Key、转写或回答正文，但第三方服务错误可能包含敏感内容，分享前请检查。重复的 ASR 中间结果不会重复刷新界面。

程序生成的日志消息使用英文；会话名称、文件路径、设备名称和系统或第三方服务返回的错误详情按原样记录，可能包含中文。

模型配置保存在 Fyne 应用配置目录下的 `model_config.json`。Windows 默认位置为 `%APPDATA%\fyne\xaux_gui\model_config.json`，其中 API Key 以明文保存在本机文件中；不要将该文件分享或提交到版本库。远程模型地址必须使用 HTTPS；HTTP 只允许用于本机回环服务。首次启动时，如果在旧会话主目录发现已有配置，会自动复制到新位置并保留旧文件。使用火山引擎等服务时，请填写其 OpenAI 兼容 API 地址以及对应的模型/推理接入点名称。

## 会话管理与历史

在 **开始 → 设置** 中输入会话主保存目录，目录会保存在应用偏好设置中。录音窗口每次统一“开始”只创建一个会话，已选中的麦克风和扬声器 WAV 保存在同一目录并登记在同一清单中；转写的一次任务也同样共享一个会话。

会话名称留空时使用当前时间。名称冲突会自动追加 `-2`、`-3` 等序号，不会覆盖已有目录。结束后输入框恢复用户最初输入的基础名称，空名称则恢复为空，下次开始重新使用当前时间。每个会话的目录结构如下：

```text
<会话主目录>/
└── <会话名称>/
    ├── session.json   # 名称、创建时间、任务类型、状态和文件清单
    ├── *.wav          # 录音文件
    ├── transcript.txt # 转写或面试的对话与结果（如有）
    ├── job_description.txt # 面试职位描述（如已填写）
    ├── summary.txt    # 转写的 AI 总结（如已生成）
    └── interview_review.txt # 面试的 AI 复盘（如已生成）
```

正常停止任务或退出应用时，会完成录音文件并保存转写和状态。通过顶部 **历史 > 会话历史** 打开历史窗口，输入关键词即可按会话名称或转写内容筛选历史记录，并自动在右侧显示首条匹配结果；也可查看任务状态、完整保存目录与转写结果，并使用录音旁的播放按钮调用系统默认播放器。没有音频数据的录音会标记为“无音频数据”，且不能播放。选中单个会话后可删除它；删除前会再次确认，并永久移除该会话目录及其中的录音和转写文件，不提供批量删除。

Windows 下播放会使用 `.wav` 的默认应用；若无法打开，请在系统设置中检查 WAV 文件的默认播放器。

## 音频链路

- `pkg/ffaudio`：按设备名称打开麦克风或 WASAPI 扬声器回采，负责采集及资源生命周期。
- `pkg/sound_cap`：统一启动、停止、暂停、恢复、状态和错误回调，将 PCM 写入 WAV，并按需送往现有 ASR 客户端。
- ASR 与录音文件固定使用 **16 kHz、单声道、signed int16 PCM**；设备原生格式会在流式处理中转换。
- 录音直接写入带正确长度的 WAV 文件，不再把整段音频保存在内存中。
- 同时选择麦克风和扬声器时，创建两路独立采集，不进行混音；转写沿用两路独立 ASR 会话。

上游 ffaudio 版本和同步范围见 [`pkg/ffaudio/UPSTREAM.md`](pkg/ffaudio/UPSTREAM.md)。

## 验证

```bash
go test ./src/... ./pkg/...
```

普通测试不要求真实声卡。以下环境变量可显式启用麦克风/扬声器采集、暂停和恢复测试：

```bash
FFAUDIO_HARDWARE_TEST=1 go test ./pkg/ffaudio -run Hardware -v
```

扬声器回采测试期间应播放系统声音；静默输出端在 WASAPI 下可能合法地返回空缓冲区。播放声音后如需强制断言回采必须产生数据，可同时设置 `FFAUDIO_REQUIRE_LOOPBACK_DATA=1`。

Linux 上可使用 `go test ./pkg/ffaudio ./pkg/sound_cap` 单独验证音频封装；完整的 `./pkg/...` 测试还需要旧版 PortAudio 和 soxr 包的开发依赖（Debian/Ubuntu：`portaudio19-dev libsoxr-dev`）。`TestPulseVirtualDevices` 是可选的隔离集成测试：设置 `XAUX_PULSE_VIRTUAL_TEST=1` 并将 `PULSE_SERVER` 指向专用的虚拟 PulseAudio 服务，按测试代码准备两个虚拟输出和一个虚拟输入；不要指向正在使用的桌面音频服务。
